# Caddy certificate and domain migration

This document owns the domain and certificate boundary for the home services.
The stable application surface is one first-level `zrr.dev` hostname per
service. `sixbones.dev` and `*.home.sixbones.dev` names are temporary aliases,
not names for new clients or configuration.

## Certificate ownership

| Path | TLS owner | Certificate |
|---|---|---|
| Public client to Cloudflare | Cloudflare edge | Universal SSL for public first-level `*.zrr.dev` names |
| Tunnel or LAN to `10.0.0.5` | Caddy | One DNS-01 `*.zrr.dev` wildcard managed by Caddy |
| Public client to Komodo Core | Cloudflare edge | `komodo.zrr.dev`, with Tunnel routing directly to `10.0.0.13:9120` |

Cloudflare and Caddy terminate different TLS connections, so the public edge
certificate cannot be replaced by Caddy while the Tunnel and Access boundary
remain. Caddy is nevertheless the only certificate manager on the origin and
LAN side. Its wildcard site aborts unknown names; exact sites generated by
caddy-docker-proxy reuse the applicable wildcard certificate on Caddy 2.10.

Cloudflare documents both the
[Universal SSL depth limit](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/limitations/)
and the fact that
[Total TLS excludes Cloudflare Tunnel hostnames](https://developers.cloudflare.com/ssl/edge-certificates/additional-options/total-tls/).
Do not solve the deep-name problem by uploading a Caddy certificate to
Cloudflare: custom edge certificates require a paid plan and would couple two
independent trust boundaries.

Canonical naming does not grant public exposure. Preserve the current Access
and Tunnel exposure service by service; default any route without an existing,
documented public policy to split DNS only. In particular, keep
`ikuai.zrr.dev` LAN-only and do not create a proxied public DNS or Tunnel route
for the router administration UI.

`scripts/check-compose.rb` is the enforced inventory. It requires each labeled
service's canonical name to be first, requires all 30 canonical names to be
unique first-level `zrr.dev` names, and rejects aliases not registered for this
migration.

## Two-phase rollout

Merging the first phase does not authorize production deployment or DNS
changes. Apply it in this order:

1. For each service that is already public, add its missing canonical hostname
   to the existing Cloudflare Tunnel, Access, and proxied DNS configuration.
   Do not broaden public exposure. Keep every old route.
2. Add canonical names to split DNS, resolving workload Caddy routes to
   `10.0.0.5`. Keep
   `komodo.zrr.dev` pointed directly at Core rather than Caddy.
3. Deploy the alias-preserving Caddy and Stack configuration. Run
   `home-verify`, then test each canonical hostname from both a public network
   and the LAN. Exercise the real Spark, n8n, Immich, and media WebSocket or
   streaming paths rather than accepting only an HTTP status.
4. Confirm an origin request presents the `*.zrr.dev` certificate, for example:

   ```sh
   curl --resolve homepage.zrr.dev:443:10.0.0.5 \
     --fail --show-error --silent --output /dev/null \
     https://homepage.zrr.dev
   openssl s_client -connect 10.0.0.5:443 \
     -servername homepage.zrr.dev </dev/null 2>/dev/null \
     | openssl x509 -noout -subject -issuer -ext subjectAltName
   ```

5. Update bookmarks, application callback URLs, mobile clients, and Homepage
   links to the canonical names. Observe access and Caddy logs for seven days.
6. Submit a second Git change that removes every registered migration alias
   from Compose, the Caddyfile, and `home-verify`. Only after that change is
   deployed and verified may the matching old Tunnel routes and DNS records be
   deleted.

The first phase is rollback-safe because the old application names remain in
every Caddy route. If a canonical path fails, stop the rollout and restore the
previous Stack revision; do not delete either DNS family while diagnosing it.

## Completion criteria

- all 30 canonical Caddy hostnames pass origin TLS and application checks;
- all public canonical names pass Cloudflare edge TLS and Access behavior;
- required WebSocket, streaming, and callback flows work on canonical names;
- no Compose label, static Caddy site, Homepage link, verification Action,
  Tunnel route, or DNS record refers to a registered migration alias;
- `komodo.zrr.dev` still bypasses workload Caddy and routes directly to Core.

Caddy storage may retain superseded certificates until its normal cleanup
window. Count active configured names and observed certificates, not leftover
files in `/data`, when deciding that the migration is complete.
